QidQuotes

Technical Infrastructure Overview — for recreation and understanding

What It Does

QidQuotes is a Telegram bot that captures funny or memorable quotes from family members, generates a beautiful illustrated quote card using AI, archives everything in a Google Sheet, and saves the image to a Google Photos album — all automatically.

You send a message in a Telegram group chat. The bot asks a few quick questions (who said it? when? is it an eggcorn?), then fires off an AI image generation job. A minute or two later the quote card appears in the chat.

Architecture at a Glance

┌──────────────────── EXTERNAL SERVICES ────────────────────────┐ │ │ │ Telegram Group Chat <──> Cloudflare Worker │ │ │ │ Google Sheets <── Worker reads/writes rows │ │ Google Photos <── Worker uploads finished images │ │ Replicate (GPT-Image-2) Worker submits jobs async │ │ └──> webhook ──> Worker when image is ready │ │ │ └─────────────────────────────────────────────────────────────────┘ No database. No server. No always-on process. State lives in Telegram message text & Google Sheets. The worker only runs when HTTP requests arrive.

The entire backend is a single Cloudflare Worker — a serverless function that wakes up on HTTP requests and goes back to sleep. There is no server to maintain, no database, and no monthly compute cost (Cloudflare's free tier is generous enough for family use).

User Flows (Step by Step)

There are three ways to submit a quote. All paths eventually reach the same image generation pipeline.

Flow B — Plain message (most common)

1
User types the quote as a plain message in the Telegram group.
2
Bot replies: "Who said this quote?" with inline buttons — one per family member. Includes a tip about scene hints.
3
User taps a name. Bot asks: "When was this said?" — Today / Yesterday buttons, or type a date.
4
Bot asks: "Is this an eggcorn?" — Yes / No. (An eggcorn is a charming word misuse, e.g. "escape goat" for "scapegoat".)
5
Bot confirms and kicks off image generation asynchronously.
6
~60–90 seconds later, the finished quote card image appears in the chat.

Flow A — Pre-tagged shortcut

Send the quote in a structured format to skip the name-selection step:

Aviya||I love bears
Aviya|05/20/2026||I love bears

Format: Name||quote or Name|MM/DD/YYYY||quote. Goes straight to the eggcorn question.

Scene hints (optional enhancement)

Add (description) at the end of any quote to guide what the illustration shows:

I love bears (bears dancing)
Ezra is my best friend (Lielle jumping with Ezra)

The text inside parentheses is stripped from the quote card text but added to the AI image prompt. If it mentions a family member's name, their reference photo is also pulled in.

How State Is Carried Between Button Presses

Cloudflare Workers are stateless — there is no in-memory session between requests. Instead, the bot embeds state directly in the text of each bot message using encoded tags. When a button is pressed, the callback reads the message text to recover context.

Message Encoded format Fields carried
Date selector 📅 [Name|quote text||scene hint] child name, quote, scene hint
Eggcorn selector 🥚 [Name|quote text||date||scene hint] child name, quote, date, scene hint

This is a simple and robust pattern — it requires no database and survives Worker restarts.

Image Generation Pipeline

When the user taps Yes/No on the eggcorn question, processQuote runs:

1
Log first. The quote is appended to Google Sheets immediately (with a blank image URL column). This gives it a row number.
2
Build the AI prompt. The prompt is assembled from: card style, reference image descriptions, who to depict (speaker as central character), scene hint, quote text, attribution, and eggcorn note if applicable.
3
Fetch reference photos. The speaker's photo (if available) is downloaded and base64-encoded. Photos of any mentioned family members are also fetched. These are sent to the model as input_images.
4
Submit to Replicate (async). The Worker POSTs to Replicate with a webhook URL pointing back to /webhook/replicate?child=…&quote=…&row=…. The Worker returns 200 immediately — it does not wait for the image.
5
Replicate calls back. When the image is done (~60–90 s), Replicate POSTs the result to the webhook URL.
6
Post to Telegram. The Worker downloads the image bytes and sends them directly to the Telegram group chat with a caption.
7
Archive to Google Photos. Image uploaded to a shared family album. The resulting permanent URL is written back to column F of the Google Sheet row.

AI prompt structure

The prompt is assembled in layers so each part is independent and composable:

[Card style: "children's" or plain based on whether speaker is adult]
[Reference image N shows [name]. ...]     ← only if photos provided
[Portrait instruction]                     ← only if speaker has photo
[Depiction: speaker as central character + any mentioned people]
[Scene inspiration from quote text + scene hint]
[Card text / attribution at the bottom]
[Eggcorn note]                             ← only if flagged

People / Names System

The "Names" tab of the Google Sheet is the entire roster of people the bot knows about. The Worker reads it fresh on every request — no code changes needed to add people.

Column A Column B Columns C, D, E …
Name Birthday (MM/DD/YYYY) Photo URL 1, Photo URL 2, … (any number)

Adult detection: anyone whose birthday makes them ≥18 years old is treated as an adult. This changes the image prompt (no "children's" style, speaker referred to by name not "the child", age omitted from attribution). This applies automatically to grandparents, parents, etc. No code change needed — just add them with a real birthday.

Likeness inclusion: if a family member's name appears in the quote text or the scene hint, their photo is pulled as an AI reference image and they are explicitly named in the "depict" part of the prompt.

Quotes Log (Google Sheet)

Col A Col B Col C Col D Col E Col F
Date Time Name Quote text Eggcorn ("yes" or blank) Image URL (Google Photos)

The row is written immediately when a quote is submitted (col F blank). Col F is updated once the image is generated and uploaded to Google Photos (~1–2 min later).

HTTP Routes (the Worker's API)

Route Caller What it does
POST / Telegram (webhook) Receives all Telegram updates (messages + button presses). Dispatches to handler logic.
POST /webhook/replicate Replicate Called when an image generation job finishes. Posts image to Telegram, uploads to Photos, updates Sheet.
POST /rerun Google Apps Script (manual) Regenerates the image for an existing row. Protected by a shared secret. Accepts optional sceneHint and isEggcorn.

Setup & Deployment (from scratch)

  1. Prerequisites: Node.js 18+, a Cloudflare account (free), a Telegram account, a Google account with Google Cloud Console access, a Replicate account.
  2. Clone the repo and run npm install.
  3. Create the Telegram bot: message @BotFather → /newbot → follow prompts → copy the token.
  4. Set up Google Cloud:
    • Create a project. Enable: Google Sheets API, Google Photos Library API.
    • Create a Service Account. Download its JSON key. Share your Google Sheet with the service account email (Editor role).
    • Create an OAuth 2.0 Client ID (Desktop app). Download credentials JSON.
  5. Get the Google Photos refresh token: node scripts/get-photos-auth.mjs. Follow the browser prompt. Copy the printed refresh token.
  6. Set up the Google Sheet:
    • Create a sheet with two tabs: Names and Quotes.
    • Names tab columns: Name | Birthday (MM/DD/YYYY) | Photo URL 1 | Photo URL 2 | …
    • Quotes tab columns: Date | Time | Name | Quote | Eggcorn | Image URL
    • Row 1 in both tabs should be headers (skipped automatically by the worker).
  7. Deploy the Worker: npm run deploy. Note the worker URL printed at the end (e.g. https://qid-quotes.your-subdomain.workers.dev).
  8. Set all secrets: run wrangler secret put <NAME> for each secret listed above.
  9. Register the Telegram webhook: npm run webhook:set. This tells Telegram to send all bot updates to your Worker URL.
  10. Add the bot to your Telegram group and send it a test quote.

Authentication Details

Google Sheets — Service Account JWT

The Worker authenticates to Google Sheets by building a signed JWT itself, using the service account's private key (stored as a Worker secret). It exchanges the JWT for a short-lived access token on each request. No OAuth flow, no redirect, no user involvement — fully automated.

Google Photos — OAuth2 Refresh Token

Google Photos requires user OAuth (it touches personal photo libraries). The one-time setup script (get-photos-auth.mjs) opens a browser, you approve access, and it prints a long-lived refresh token. The Worker stores this token as a secret and exchanges it for a new access token on each upload.

Replicate — Simple API token

Replicate uses a plain Bearer token in the Authorization header. No complexity.

Design Decisions Worth Knowing

Why Cloudflare Workers? Generous free tier (100,000 requests/day), global edge deployment, and zero maintenance. No server to babysit. The whole backend is one npm run deploy.
Why no database? State is encoded in Telegram message text between steps, so the Worker can be stateless. Persistent data (quotes, names) lives in Google Sheets which the family can view and edit directly.
Why async image generation? AI image generation takes 60–90 seconds, far longer than the 30-second limit Telegram allows for a webhook response. The Worker submits the job to Replicate and returns 200 immediately. Replicate calls back the Worker when the image is ready.
Why GPT-Image-2 on Replicate? It supports multiple reference images (input_images) so family member photos can guide the likeness in the illustration. Replicate also handles async webhooks natively.
Photo URLs in the Names tab: Any publicly accessible image URL works. Google Drive share links and Dropbox share links also work (the Worker follows redirects when fetching photos).

QidQuotes — all code lives in src/. No framework, no ORM, no auth library — just TypeScript and fetch().
